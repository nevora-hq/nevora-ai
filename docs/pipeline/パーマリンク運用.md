# 記事のURL(パーマリンク)の運用(2026-11-22 新設)

## 形
- 記事のURLは `/posts/大/中/小-NN`(例: `/posts/image/prompting/same-character-01`)。
- 大=カテゴリ(12種。英小文字のスラッグ)、中=カテゴリ内の分類、小=記事の項目+連番(同じ小項目が増えたら -02、-03)。
- **大・中・小の分類名は、サイトの画面には出さない**(URL・canonical・構造化データ・サイトマップにだけ現れる)。

## 対応表
- `サイト運営/サイト本体/lib/permalinks.json`(`posts` のキー=記事ファイル名から日付 `YYYY-MM-DD_` を除いた部分)。公開キューが日付を付け替えても URL は変わらない。
- 記事のファイル名(slug)・本文中の内部リンク(`/posts/<slug>`)は従来のまま書く。サイトが表示のときに新URLへ解決する(`lib/permalinks.js` の `rewritePostLinks`)。
- **新しい記事を作るときは、対応表に1行足す。** 足さないと、ビルドが警告を出し、その記事は旧形式(`/posts/<slug>`)のURLになる。大(先頭)は、記事の `category` と対応表の `categories` が一致していること。
- 記事数が増えたら、中・小の分類を足してよい(既存記事のURLを変えるときは、旧URLを `vercel.json` で転送すること)。

## 旧URLの転送(301)
- 旧URL(`/posts/日付_題`)→新URLの転送は、サイト本体の `vercel.json`。台帳は `lib/legacy-slugs.json`(公開済みだった38本)。
- 作り直しは `node scripts/generate-vercel-redirects.js`、照合は `--check`。公開キューで新しく公開される記事は最初から新URLなので、転送は増えない。

## 仕組みの場所
- `lib/permalinks.js`(`postHref`・`permalinkSegments`・`rewritePostLinks`)、`pages/posts/[...slug].js`(ページ)、`lib/posts.js`(各記事に `href` を付ける)、`scripts/permalink-path.js`(スクリプト用)。

## 確認(push の5分後)
- トップ200・sitemap の記事URLが記事数と同じ・新URLの記事ページ200・旧URLが新URLへ301・記事内リンクに旧形式が無い。
