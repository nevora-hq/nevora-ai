# 出典フォーマット仕様(sources)

記事frontmatterの `sources` フィールドで出典を構造化して管理する仕様。実装は `lib/posts.js`(`normalizeSources`)・`components/ArticleSources.js`。

## 背景

出典が「トップページURL」「解説メディアのランキング記事」のみで、一次情報(公的機関・学会・論文・業界団体・開発元・提供元の公式)が不足する状態を防ぐ(`docs/audit-report.md` 観点2〔このサイトには無い。読まずに進める〕)。従来の出典は本文末尾の「## 出典一覧」見出し+自由形式Markdownリンクのみで、一次/二次の区別・URLの深さ・編集部独自調査であることの明示が構造化されていなかった。

この仕様は、B3(出典の弱さ)の再発をコード側で検知しやすくすることと、フェーズ7(記事自動生成プロンプト改訂)で新規記事が最初から一定水準の出典を持つことを目的とする。

## 出典の決まり(依頼者の決定「AI記事は出典無くてもOK」)

- `sources` は、確認メモ(sources.md)にある公式の情報(提供元の公式ページ・公的機関・法令など)があるときだけ載せる。無ければ載せなくてよい。確認メモに無い出典を載せない。
- 具体的な数字・料金・機能・モデル名・法律や規約の内容は、企画の段階では出典を探さず、本文に入れて書き、本文を書き終えたあとに公式の情報で確かめ、確認メモに、その文・確かめた先(URL)・確認日を書く。違っていたらその事実だけを直し、確かめられなかった内容は外すか言い直す(writer.md 規則11(6))。
- 本文には出典を表示しない。出典は、記事の末尾の出典の欄(`sources`)だけに載せる(依頼者の決定「毎回出典を記載するの禁止。記事末にある出典のみにすること。」)。本文に `%%出典:…%%` の印を書かない(新しい原稿には書かない。既存の原稿に残っている印は、コードが画面に出さないので、消さなくてよい。印は原稿に残してよい)。「〜によると」等の出典の飾りも書かない(機関の見解・方針そのものを伝える文で機関名を主語にするのは、機関名の書き方の決まりどおり可)。
- 出典を理由に差し戻してよいのは「記事にある具体的な数字・料金・機能・モデル名・法律や規約の内容が、確認メモに無い」の1つだけ。`type`・順位(一次/二次/編集部調査)・出典の欄の形は、報告のみで差し戻し理由にしない。以下の `type` と検証の記述は、書き方の目安であり、差し戻しの基準ではない。

## frontmatterスキーマ

```yaml
sources:
  - label: "文化庁 AIと著作権について"
    url: "https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html"
    type: "primary"
  - label: "◯◯(AI解説メディア)の解説記事"
    url: "https://example-media.jp/column/xxxx"
    type: "secondary"
  - label: "編集部調査"
    type: "editorial"
    surveyN: 20
    surveyMethod: "アンケート(NEVORA読者)"
    surveyDate: "2026-08"
```

### フィールド

| フィールド | 必須 | 説明 |
|---|---|---|
| `label` | 必須 | 出典の表示名(サイト名・調査名など) |
| `type` | 必須 | `primary`(一次情報) / `secondary`(二次情報) / `editorial`(編集部調査)のいずれか |
| `url` | `primary`/`secondary`で必須 | 該当ページの**深いURL**(トップページのみは警告対象。判定は「pathnameが空または`/`のみ」の簡易チェック) |
| `surveyN` | `editorial`で必須 | 調査のn数(サンプル数) |
| `surveyMethod` | `editorial`で必須 | 調査方法(例:「アンケート」「編集部内ヒアリング」) |
| `surveyDate` | `editorial`で必須 | 実施時期(例:「2026-08」) |

### type の使い分け

- **primary(一次情報)**: AI開発元・サービス提供元の公式・公的機関・学会・論文・業界団体など、情報の一次発信元。
- **secondary(二次情報)**: AI解説メディア・ITニュースサイトの解説記事等、一次情報を紹介・解説している情報源。一次情報が別途無い場合の補助として使う。
- **editorial(編集部調査)**: NEVORA編集部が独自に行った調査・ヒアリング・試算。フェーズ1指示7項の方針により、非公式調査であっても「編集部調査(n数・調査方法・実施時期を明記)」として正直にラベリングすれば独自データとしての強みになる、という考え方に基づく。n数等が記録に無く明記できない場合は、この`sources`に載せず本文中で「筆者調べ」等の表現も使わない(削除するか、明記できる形に調べ直す)。

**primary/secondaryの区分基準の補足(フェーズ5)**: 「本文中で直接引用しているかどうか」と「一次情報か二次情報か」は独立した属性であり、混同しないこと。一次情報とは情報の発生源(開発元・提供元の公式・公的機関・査読論文・編集部が自ら実施した調査)を指す。AI解説メディア・比較サイト等の編集メディアは、本文中で直接引用していても情報の発生源ではないためsecondaryのままである。

## バリデーション(ビルド時警告。参考であり、差し戻し理由にしない)

`lib/posts.js` の `normalizeSources` が以下をチェックし、違反時は `next build`/`next dev` のログに `console.warn` を出す(**ビルドは失敗させない**。記事データはMarkdownで人手管理のため、軽微な入力漏れでビルド全体を止めると運用の障害になるため)。

- `label` が空
- `type` が `primary`/`secondary`/`editorial` 以外(未指定含む)→ `secondary` 扱いにフォールバック
- `primary`/`secondary` で `url` が空、またはトップページ相当(浅いURL)
- `editorial` で `surveyN` / `surveyMethod` / `surveyDate` のいずれかが空

## 表示

`components/ArticleSources.js` が `post.sources` を受け取り、記事末尾(悩みチップの後、参考情報の明記の前)に「出典」見出し+リストとして描画する。`type` ごとにバッジ(一次情報/二次情報/編集部調査)を表示する。`sources` が空配列の記事ではコンポーネントは何も描画しない。

## 既存記事(本文「## 出典」セクション)との関係

**一斉移行はしない。** 全記事のうち、`sources` が設定されているのは今後フェーズ5・通常の記事修正のついでに移行した記事のみで、それ以外の記事は従来通り本文中の「## 出典」見出し+Markdownリンクがそのまま表示される(後方互換。新規記事では本文に出典を書かず、出典の欄だけにする)。

- `sources` が設定された記事は、本文側の「## 出典」セクションを**削除すること**(残すと出典が二重表示される)。
- 削除を忘れた場合、`lib/posts.js` の `getPostBySlug` が `sources` と本文の `## 出典`/`### 出典` 見出しの共存をビルド時に検知し、`console.warn` で警告する(自動では本文側を削除しない。正規表現によるHTML分割はB1/B2と同種の不具合を招くリスクがあるため)。

## 出典の検証基準(フェーズ5標準ルール。参考。差し戻し理由にしない)

出典URLを追加・移行する際は、次の2段階を満たすことを目安にする。確認メモに無い出典は載せない。**「URLが実在する」ことと「そのURLが記述内容の根拠になる」ことは別物であり、前者だけでは出典として不十分。**

1. **実在確認**: URLが実在し、リンク切れでないこと(WebSearch等で確認)。
2. **裏付け確認**: そのページの内容が、記事本文の当該記述を実際に裏付けているか(組織のトップページ・関連ページというだけで、記述内容そのものには触れていない、ということがないか)を確認すること。

裏付け確認の結果に応じて、以下のいずれかで対応する。

- **完全に裏付ける** → そのまま`primary`/`secondary`として採用。
- **部分的にしか裏付けない**(例:出典1件で2つの主張をカバーしようとしていたが、片方しか支持しない) → 出典を分割し、それぞれが実際に裏付ける範囲だけをラベルに明記する。
- **裏付けを直接確認できない**(検索がJavaScript駆動で結果を直接確認できない等) → `primary`として扱わず`secondary`に格下げし、ラベルに確認状況(例:「要人手検索確認」)を明記する。実在すら確認できない場合は出典として使わない。

フェーズ5の出典差し替え作業全体で標準として適用すること。

## 移行済みの見本記事

見本記事: (未確定: AIサイトの記事から選び直す)。フェーズ5で他記事を移行する際のテンプレートとして参照すること。

## 移行方針

- フェーズ5(出典の弱い記事)の差し替え作業で、対象記事から順次この形式に移行する。
- フェーズ5対象外の記事は、期限を設けず、内容修正の機会があるついでに移行する。
- フェーズ6(記事自動生成プロンプト改訂)以降の新規記事は、確認メモ(sources.md)にある公式の情報があるときだけ `sources` を置く(`.claude/agents/writer.md` の規則11(6))。無くてよく、無いことを理由に差し戻さない。
